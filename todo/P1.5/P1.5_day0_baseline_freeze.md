# P1.5 Day 0 - Baseline Freeze

优先级：最高之前的准备日。

目标：先冻结当前行为基线，避免后续迁移时分不清“改坏了什么”和“本来就这样”。Day 0 不做结构改造，只做证据留存和回归基准建设。

## 实现要求

- 冻结基线时要按当前图结构和节点职责记录，不要把记录工具和业务逻辑写混在一起
- baseline 采集、trace 保存、图导出要各自独立，便于后续替换
- 这一天只做观测和留痕，不要为了方便把基线逻辑塞进业务文件

## 这一天要解决什么

- 把当前图和关键路径导出
- 把现有测试、SSE、trace、响应样本保留下来
- 把后续必须持续绿色的 case 先固定为 baseline
- 让 Day 1 - Day 7 都能对照这份基线判断是否回归

## 明确不做什么

- 不改任何业务节点
- 不改任何路由语义
- 不改任何数据结构
- 不改任何 SSE payload
- 不改任何测试断言

## 需要冻结的基线内容

### 1. 当前图结构

要导出并保存：

- 当前 `graph.png`
- 当前 Mermaid 图
- 当前顶层节点列表
- 当前关键边关系

重点关注：

- `load_context`
- `understand_turn`
- `route_gate`
- `plan_execute_subgraph`
- `rag_subgraph`
- `recommendation_subgraph`
- `tool_subgraph`
- `compose_answer`
- `persist_session`
- `emit_final`

### 2. 当前测试基线

至少保留以下测试的基线结果：

- 路由矩阵
- answer verifier
- langgraph smoke
- stream / SSE 相关测试
- tool / RAG / plan 执行相关测试

### 3. 当前关键 case 追踪

建议保存这些类别的 baseline：

- 低信息 / 纯标点
- identity / capability
- direct_chat
- 单店查券
- 单店营业状态
- 单店评价 / 场景
- recommendation
- comparison
- planning
- query merge / 指代消解
- unsafe / prompt injection
