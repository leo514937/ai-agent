# P1.5 Day 4 - Standard Path Contract Review

优先级：第四。

目标：把 standard path 改造成 Contract 驱动的稳定路径，补齐 simple 路径的 `rule_review`，并让 standard review 成为契约级兜底，而不是 Planner 级回退。

## 这一天要解决什么

- standard path 不再由 Router 直接决定能力组合
- standard path 由 `SourceContract` 约束 rag / tool / recommendation
- simple path 必须显式经过 `rule_review`
- `recommendation_reason` 从纯 `rag` 调整为 `mixed/internal`
- `AnswerContract.forbidden_facets` 参与最终裁剪与修复

## 实现要求

- standard path 要按图落地成稳定的节点链，不要把合并、排序、契约校验、最终回答都堆到一个函数
- `SourceContract`、`rule_review`、`contract_review`、`merge_rank_node` 要分层实现
- 契约校验和答案修复要拆开，不要让一个节点既管证据又管修复又管生成
- standard path 的代码要尽可能贴近图结构，方便调试和回归

## 明确不做什么

- 不让 standard review 回 `planner_node`
- 不把 standard path 变成 Planner path
- 不删除旧 `compose_answer` 兼容出口
- 不改变单店 `TargetShopPolicy` 结果语义

## 标准路径的目标结构

建议 standard path 语义如下：

1. `hard_guard`
2. `understand_turn`
3. `resolve_target_shop`
4. `build_answer_contract`
5. `build_source_contract`
6. `workflow_executor`
7. `select_required_sources`
8. `rag_node / tool_node / recommendation_node`
9. `merge_rank_node`
10. `contract_review`
11. `final_answer`

## 重点任务

### 1. `hard_guard`

这一层要在前面显式存在，负责挡住无效输入、低信息输入、明显澄清需求。

### 2. `SourceContract`

这是 Day 4 的核心。

建议它负责：

- 定义 `facet -> source`
- 定义 `required / optional / forbidden facets`
- 定义当前任务是单店、候选店还是比较店
- 定义哪些信息一定要 tool、哪些可以 rag

建议默认映射保持清晰：

- `coupon / open_status / distance` -> `tool`
- `scene_fit / review_summary` -> `rag`
- `recommendation_reason` -> `mixed/internal`

这样做的目的是：

- 防止查券时回答环境、口味、服务等无关内容
- 防止工具和 RAG 混用时边界不清

### 3. `rule_review`

Simple path 的 review 必须是规则级别。

适合检查：

- 是否已经有足够信息直接答
- 是否只需要轻微修复
- 是否应当降级而不是继续调用更多能力

### 4. `contract_review`

Standard path 的 review 是契约级别，不是重规划。

允许动作：

- `pass`
- `repair_answer`
- `retry_rag`
- `retry_tool`
- `degrade`

明确禁止：

- `replan`
- 回 `planner_node`

### 5. `merge_rank_node`

这一层建议承担：

- 聚合 rag / tool / recommendation 结果
- 做轻量排序
- 生成给 review 使用的中间态

但它不应该再承担：

- 路由决策
- 重试决策
- Planner 级回退

## Day 4 输出要求

Day 4 结束后，仓库应该满足：

- simple 路径显式经过 `rule_review`
- standard path 由 `SourceContract` 驱动
- `contract_review` 成为 standard path 的主兜底
- `recommendation_reason` 来源改成 `mixed/internal`
- standard review 不会回到 `planner_node`

## Day 4 验收

1. simple 路径显式经过 `rule_review`
2. standard review 不回 `planner_node`
3. `recommendation_reason` 来源改成 `mixed/internal`
4. `SourceContract` 能驱动 rag/tool/recommendation 的选择
5. 旧 trace 字段继续写
6. 旧 SSE 输出继续写
7. 旧 `compose_answer` 仍可作为出口兼容层
