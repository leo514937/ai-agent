# 05_工具执行层

# 一、层职责

工具执行层负责通过 ToolCall 获取真实数据。

所有事实都必须来自这一层。

本层核心目标：

1. 工具可注册、可发现；
2. 工具调用统一入口；
3. 工具参数可校验；
4. 工具执行可重试、可熔断、可降级；
5. 工具结果结构统一；
6. 并行调用可控；
7. 每个结果可追踪到 `trace_id/call_id/shop_id/tool_name`。

# 二、ToolRegistry 与 ToolCallGateway 的区别

这部分需要明确，不要混在一起。

```text
ToolRegistry：负责注册工具、管理工具元信息。
ToolCallGateway：负责统一调用工具、做校验、重试、熔断、降级、日志。
ToolExecutor：负责真正执行某个具体工具。
```

调用关系：

```text
LLM / Planner
  ↓ 生成 ExecutionPlan
ToolCallGateway
  ↓ 查询工具是否存在
ToolRegistry
  ↓ 获取工具定义、schema、timeout、retry 策略
ToolCallGateway
  ↓ 参数校验、并发控制、重试、熔断、降级
ToolExecutor
  ↓
真实工具 / Java 接口 / DB 服务 / HTTP 服务
```

不要把所有工具写死在 Gateway 里，否则 Gateway 会同时承担注册、调用、重试、熔断、日志，职责过重。

# 三、模块划分

| 模块 | 作用 |
|---|---|
| ToolRegistry | 注册工具和工具元信息 |
| ToolCallGateway | 工具统一调用入口 |
| ToolSchemaValidator | 校验工具参数和输出 |
| ToolExecutor | 执行具体 ToolCall |
| RetryManager | 控制重试 |
| CircuitBreakerManager | 控制熔断 |
| ToolResultNormalizer | 标准化工具结果 |
| ToolTraceLogger | 记录工具调用日志 |
| BatchToolExecutor | 批量并行工具执行 |
| TimeoutController | 控制单工具和整轮 deadline |

# 四、ToolRegistry

## 4.1 作用

ToolRegistry 管“有哪些工具”。

它回答：

- 系统有哪些工具；
- 每个工具叫什么；
- 输入 schema 是什么；
- 输出 schema 是什么；
- 超时时间是多少；
- 最多重试几次；
- 是否允许并行；
- 失败后如何降级；
- 是否允许被当前 Agent 调用。

## 4.2 工具注册示例

```json
{
  "tool_name": "get_coupon_list",
  "required_fields": ["shop_id"],
  "timeout_ms": 1500,
  "max_retries": 2,
  "risk_level": "normal",
  "fallback": "coupon_unknown",
  "circuit_breaker_enabled": true,
  "parallel_allowed": true,
  "output_status_enum": ["ok", "empty", "unknown", "failed"]
}
```

## 4.3 当前工具清单

```text
resolve_shop
search_shops
get_shop_detail
get_coupon_list
check_open_status
get_distance_eta
```

# 五、ToolCallGateway

## 5.1 作用

ToolCallGateway 管“怎么统一、安全、可靠地调用工具”。

执行步骤：

1. 接收 `ExecutionPlan`；
2. 检查工具是否注册；
3. 校验参数；
4. 检查熔断状态；
5. 控制并发和 deadline；
6. 执行 ToolCall；
7. 根据错误类型决定是否重试；
8. 重试失败后降级；
9. 标准化 ToolResult；
10. 写入 trace。

## 5.2 Gateway 伪代码

```python
class ToolCallGateway:
    def __init__(self, registry, executor, retry_manager, circuit_breaker, normalizer):
        self.registry = registry
        self.executor = executor
        self.retry_manager = retry_manager
        self.circuit_breaker = circuit_breaker
        self.normalizer = normalizer

    async def call(self, tool_name: str, args: dict, call_id: str, trace_id: str):
        tool_def = self.registry.get(tool_name)
        if not tool_def:
            return ToolResult.failed(call_id, tool_name, "TOOL_NOT_REGISTERED")

        validate_args(tool_def.input_schema, args)

        if self.circuit_breaker.is_open(tool_name):
            return ToolResult.unknown(call_id, tool_name, "CIRCUIT_OPEN")

        raw_result = await self.retry_manager.run(
            lambda: self.executor.execute(tool_def, args),
            retry_policy=tool_def.retry_policy
        )

        return self.normalizer.normalize(raw_result, tool_def, call_id, trace_id)
```

# 六、工具契约设计

每个工具都要有完整 contract。

```json
{
  "tool_name": "get_coupon_list",
  "input_schema": {
    "shop_id": "string"
  },
  "output_schema": {
    "status": "ok|empty|unknown|failed",
    "coupons": []
  },
  "business_empty_meaning": "工具成功，确认暂无可用券",
  "retryable_errors": ["TOOL_TIMEOUT", "NETWORK_ERROR", "SERVICE_UNAVAILABLE"],
  "non_retryable_errors": ["INVALID_SHOP_ID", "PERMISSION_DENIED"],
  "freshness": "realtime",
  "cache_policy": {
    "enabled": false
  }
}
```

必须明确：

1. 空数组是“确认没有”，还是“没查到”；
2. 过期券是否返回；
3. 不可用券是否返回；
4. 团购券、代金券是否区分；
5. 多张券如何摘要；
6. 输出是否实时；
7. 是否允许缓存。

# 八、批量并行工具调用

Gateway 除了单工具执行，还要支持批量并行。

## 8.1 批量调用输入

```json
{
  "tool_calls": [
    {
      "call_id": "c1",
      "shop_id": "shop_001",
      "tool_name": "get_shop_detail",
      "args": {"shop_id": "shop_001"},
      "required": true
    },
    {
      "call_id": "c2",
      "shop_id": "shop_001",
      "tool_name": "get_coupon_list",
      "args": {"shop_id": "shop_001"},
      "required": false
    }
  ],
  "max_concurrency": 8,
  "deadline_ms": 6000
}
```

## 8.2 批量调用规则

1. `resolve_shop` 之前不能并行调用单店工具；
2. 拿到 `shop_id` 后，detail / coupon / open / distance 可以并行；
3. 每个 ToolResult 必须携带 `call_id`、`shop_id`、`tool_name`；
4. 并行调用必须受 `max_concurrency` 和 `deadline_ms` 控制；
5. optional 工具失败不阻塞整轮回答，只标记 unknown；
6. required 工具失败时，根据任务类型终止、澄清或降级；
7. 批量结果必须按 `shop_id` 聚合，防止串店。

# 九、RetryManager

可重试错误：

```text
TOOL_TIMEOUT
NETWORK_ERROR
SERVICE_UNAVAILABLE
DB_CONNECTION_BUSY
TEMPORARY_INTERNAL_ERROR
RATE_LIMIT_TEMPORARY
```

不可重试错误：

```text
SHOP_NOT_FOUND
AMBIGUOUS_SHOP
COUPON_NOT_FOUND
INVALID_ARGUMENT
PERMISSION_DENIED
INVALID_SHOP_ID
BUSINESS_RULE_REJECTED
```

默认策略：

```json
{
  "max_retries": 2,
  "backoff": "exponential",
  "initial_delay_ms": 200,
  "max_delay_ms": 800,
  "jitter": true
}
```

# 十、CircuitBreakerManager

熔断状态：

```text
CLOSED：正常调用
OPEN：熔断打开，直接降级
HALF_OPEN：半开探测
```

建议配置：

```json
{
  "window_seconds": 60,
  "min_calls": 20,
  "failure_rate_threshold": 0.5,
  "consecutive_failure_threshold": 5,
  "slow_call_threshold_ms": 2000,
  "open_duration_ms": 30000
}
```

熔断降级：

| 工具 | 熔断后表达 |
|---|---|
| get_coupon_list | 优惠信息 unknown |
| check_open_status | 营业状态 unknown |
| get_distance_eta | 距离 ETA unknown |
| search_shops | 推荐无法继续 |
| resolve_shop | 单店目标无法确认 |

# 十一、ToolResult 标准结构

```json
{
  "call_id": "c2",
  "shop_id": "shop_001",
  "tool_name": "get_coupon_list",
  "success": false,
  "result_status": "unknown",
  "data": null,
  "error": {
    "code": "TOOL_TIMEOUT",
    "message": "coupon service timeout"
  },
  "source": "coupon_service",
  "timestamp": "2026-06-19T10:00:00+09:00",
  "trace_id": "trace_001",
  "retry_count": 2,
  "degraded": true,
  "circuit_open": false,
  "cache_hit": false,
  "freshness": "realtime",
  "can_answer_definitively": false
}
```

# 十二、结果状态语义

| result_status | 含义 | 回答层能否确定性表达 |
|---|---|---|
| ok | 工具成功并返回有效数据 | 可以 |
| empty | 工具成功并确认无数据 | 可以，但只能说确认暂无 |
| unknown | 工具未能确认 | 不可以 |
| failed | 工具失败或参数错误 | 不可以 |
| circuit_open | 熔断直接降级 | 不可以 |

重点：

- `unknown` 不能说成“没有”；
- `failed` 不能隐藏；
- `empty` 才能说“确认暂无”；
- `circuit_open` 要在回答中说明暂时无法确认。

# 十三、本层实现注意事项

1. LLM 不直接调用底层工具。
2. Planner 不直接执行工具。
3. Gateway 不写死工具业务逻辑。
4. ToolRegistry 不执行工具。
5. ToolExecutor 不处理回答文案。
6. ToolResult 必须标准化后才能进入回答层。
7. 每个 ToolCall 都要有 trace。
8. 批量并行一定要按 shop_id 聚合结果，防止串店。
