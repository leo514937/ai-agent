# Chat 接口 E2E 全链路实测报告

## 结论

**PARTIAL PASS**

这次已经基于真实 `chat` 接口把文档中的样例全部跑过一遍，主链路大部分是通的，但还没有全部收口。  
尤其是：

- `你能帮我做什么？` 仍然没有稳定返回能力介绍
- `帮我下单并支付` 的安全拒绝在这次实测里没有稳定呈现
- `便宜一点的呢` 在真实 chat 续问里仍不稳定
- `第二家有券吗` 仍没有稳定命中 comparison 上下文第二项

## 实测方式

- 入口：`POST /internal/v1/chat/stream`
- 运行方式：`fastapi.testclient.TestClient`
- 真实链路：`run_agent_graph(...)`
- 数据源：真实运行结果写入 `todo/chat_e2e_full_chain_actual_run_results.json`
- 说明：这次为了避免 Windows 上 `python_service.log` 轮转锁文件，临时关闭了 file logger，避免测试本身被日志噪音打断

## 总体结果

- 总样例数：`20`
- 明显通过：`11`
- 部分通过：`5`
- 失败：`4`

## 关键结论

### 已经稳定的部分

- 单店优惠券查询
- 单店营业状态查询
- 推荐主链路
- 推荐后 `第一家有券吗`
- 对比主链路
- 未知 facet 的明确澄清
- exploration / 路线类的起点澄清

### 仍然有问题的部分

- 能力介绍类 query 仍没有稳定走到 direct answer
- 安全拒绝类 query 仍没有稳定给出明确拒绝文案
- 推荐续问 `便宜一点的呢` 在真实 chat 接口仍然回落成泛化澄清
- 对比后续问 `第二家有券吗` 仍没有稳定吃到 comparison 上下文
- 单店距离类 query 仍会先走歧义澄清

## 和“刚刚改动”的关系

你刚刚让我收的两类中等难度问题，在单测/局部路径上已经有明显改善，但这次真实 chat E2E 还没完全收住：

- `便宜一点的呢`
  - 单测里已经能把它恢复成 `recommendation_refine`
  - 真实 chat 接口里仍有回落，说明这条链路还没完全吃到预期上下文
- `第二家有券吗`
  - 单测里已经能优先走 comparison 上下文
  - 真实 chat 接口里还会要求重新指定店铺，说明 comparison 后续引用还没完全稳定

所以结论不是“都已经改好了”，而是：

- **局部测试通过了**
- **真实 chat E2E 还没完全收口**

## 主要问题归类

### 1. 能力 / 安全类 direct response 仍不稳定

- `你能帮我做什么？`
- `帮我下单并支付`

这两条在真实 chat 里没有稳定给出文档预期的回答。

### 2. 续问类还没完全稳住

- `便宜一点的呢`
- `第二家有券吗`

这两条在真实 chat 里都还会掉回澄清或重新选店。

### 3. 单店距离类仍偏保守

- `海底捞水晶城店多久能到？`

实际表现是先澄清候选店，而不是直接进入距离查询。

### 4. 推荐结果有重复门店

- `推荐几家性价比高的烧烤`

结果能出，但存在重复推荐项，推荐多样性还不够好。
