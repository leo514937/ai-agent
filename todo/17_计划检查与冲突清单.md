# 11. 计划检查与冲突清单

## 结论
当前这套本地生活 Agent 计划在补齐服务边界后，整体已经是**可实施**的，但更准确地说是“设计完整、实现缺口仍大”。  
本文件用于记录我对 `todo/00` 到 `todo/10` 的冲突检查结果，以及已经做过的最小修订。

## 图形态结论

- 当前编排图应该被定义为带状态和回边的 LangGraph `StateGraph`，不是纯 DAG。
- 之所以允许回边，是因为 `answer_verify -> rewrite -> answer_generate`、`target_resolve -> clarify_response -> check_pending_clarification`、`fallback` 降级等都属于真实运行需求。
- 因此，不需要把现有规划改成纯 DAG；需要改的是文档术语，明确“主图允许回边，DAG 只作为单轮快照”。

## 已做的修订
- 在 [01_冻结MVP范围和测试用例.md](./01_冻结MVP范围和测试用例.md) 中补了“独立 Agent 运行时”边界说明，避免把计划误读成当前 `com.hmdp.ai` 代理层的局部补丁。
- 在 [09_实现输入层_HardGuard_顶层意图.md](./09_实现输入层_HardGuard_顶层意图.md) 中把 `HardGuard` 分类和 `TopIntent` 枚举分离，避免两个层次互相混用。
- 在 [02_状态转移与路由决策表.md](./02_状态转移与路由决策表.md) 中补了 `tool_execute -> circuit_open` 的状态转移。

## 仍然存在的实现缺口
这些不是文档冲突，而是后续必须补的工程缺口：

- 还没有真正的 `LangGraph` 节点、边、状态字段表。
- 还没有 `Streaming Event` 协议表。
- 还没有 `SessionStore`、`ToolExecutor`、`AnswerVerifier` 的代码实现。
- 现有仓库里的 AI 入口仍是远端代理式实现，和计划中的 Agent 主体不是一回事。
- 现有测试基线不稳，`AiAssistantServiceRecommendTest` 和 `AiAssistantStreamServiceTest` 目前需要补依赖注入，否则不能作为 Agent 重构护栏。

## 每阶段完成后的固定动作

为避免 coding agent 一次性无脑跑完整条链路，每个阶段结束后都必须执行下面 4 个动作，再进入下一阶段：

1. 跑该阶段对应的验收测试。
2. 检查这次改动有没有越过阶段边界。
3. 更新本文件里的冲突与完成记录。
4. 只有测试通过才允许进入下一阶段。
