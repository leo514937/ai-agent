## 3.1 新增核心抽象

### CandidateSpec（domain/candidate_spec.py → 新增）

```python
@dataclass
class CandidateSpec:
    """用户想找什么样的候选。"""
    source: str                           # explicit / discovery / context / mixed
    category: str                         # 品类："KTV", "火锅"
    query: str                            # 原始查询文本
    location_scope: dict | None           # 位置范围
    sort_by: list[dict]                   # [{"field": "rating", "order": "desc"}]
    limit: int = 2                        # 需要的候选数
    explicit_mentions: list[str] = None   # 显式店名
    context_ref: str | None = None        # "这家"/"第一家"
    filters: dict = None                  # 筛选条件
    ranking_signals: dict = None           # 排名信号
```

### ResolvedCandidate（domain/candidate_spec.py → 新增）

```python
@dataclass
class ResolvedCandidate:
    """已绑定 shop_id 的候选。"""
    shop_id: str
    shop_name: str
    source: str               # explicit / discovery / context
    rank: int = 0
    confidence: float = 1.0
    # 可选基础字段（候选发现阶段就会有的）
    rating: float | None = None
    distance_km: float | None = None
    open_status: str | None = None
    coupon_count: int | None = None
```

### CandidateSet（domain/candidate_spec.py → 新增）

```python
@dataclass
class CandidateSet:
    """候选集合。"""
    status: str               # resolved / insufficient / ambiguous / not_found
    source: str               # explicit / discovery / context / mixed
    candidates: list[ResolvedCandidate]
    warnings: list[str] = None
    original_spec: CandidateSpec | None = None
    min_required: int = 2
    max_allowed: int = 5
```

## 3.3 target_resolve 拆分

### 改前：一个函数处理所有 case

```
_h_target_resolve (300行)
  ├── recommendation → 合成 RESOLVED
  ├── comparison → 硬解析 ≥ 2 shop_id
  └── single_shop → resolve_shop()
```

### 改后：拆为三个阶段

```
_h_target_resolve → 改为薄调度层
  ├── _resolve_explicit_targets()    # explicit shop → resolve_shop()
  ├── _resolve_context_targets()     # ordinal/deictic → session 恢复
  └── _resolve_discovery_targets()   # candidate_spec → search_shops → CandidateSet
```

其中新增的 `_resolve_discovery_targets()`：

```python
def _resolve_discovery_targets(state) -> dict:
    """为 discovery comparison 创建 CandidateSet，不要求立即 resolve shop_id。"""
    spec = _build_candidate_spec(state)
    # 执行 search_shops 获取候选
    search_result = dispatch_tool_call("search_shops", {
        "query": spec.query or spec.category,
        "location": MOCK_LOCATION,
        "limit": spec.limit * 2,  # 多取一些以备过滤
    })
    candidates = _search_result_to_candidates(search_result, spec)
    if len(candidates) >= spec.limit:
        return {
            "candidate_set": CandidateSet(
                status="resolved",
                source="discovery",
                candidates=candidates[:spec.limit],
                original_spec=spec,
                min_required=spec.limit,
            )
        }
    return {"candidate_set": CandidateSet(status="insufficient", ...)}
```

**修改文件**：
- `engine/graph_builder.py`：重构 `_h_target_resolve`，提取子函数
- `target/shop_resolver.py`：无变化

## 3.4 comparison 校验拆为两段

### 改前：一个阻塞点

```python
# L1199-1205
if len(resolved_targets) < 2:
    return "对比至少需要两家不同的店"
```

### 改后：分 discovery 前/后两段

**前置校验**（在 target_resolve 中）：

```python
if comparison_requested:
    # 检查是否有候选来源
    has_explicit = len(explicit_mentions) >= 2
    has_context = len(context_resolved) >= 2
    has_discovery = bool(candidate_spec)  # ★ 新增
    
    if not (has_explicit or has_context or has_discovery):
        return "对比至少需要两家不同的店"  # 真·无法比较
    # 有候选来源 → 继续

if candidate_set.status != "resolved":

```

## 3.5 改造后的 comparison 完整链路

### explicit comparison（不变）

```
语义解析(merchant_mentions=["海底捞","山城一锅"])
  → target_resolve: resolve_shop() → 2 shop_id → RESOLVED
  → comparison_planner: 生成 tool_calls
  → tool_execute → evidence_build(comparison_matrix) → answer
```

### discovery comparison（新增链路）

```
语义解析(candidate_source="discovery", candidate_category="KTV",
         candidate_sort_by=[{field:"rating",order:"desc"}], candidate_limit=2)
  → target_resolve:
      _resolve_discovery_targets()
      → search_shops → 取 top 2 → CandidateSet(status=resolved)
      → 返回 RESOLVED（携带 CandidateSet）
  → comparison_planner:
      从 CandidateSet 取 shop_id
      生成 get_coupon_list / check_open_status 等 tool_calls
  → tool_execute → evidence_build(comparison_matrix) → answer
```

### context comparison（优化）

```
语义解析(deictic_references=["刚才推荐的几家"])
  → context_recovery:
      resolve_references() → 从 session 恢复 candidate list
  → target_resolve:
      _resolve_context_targets() → ≥ 2 shop_id
  → comparison_planner → tool_execute → evidence → answer
```

### mixed comparison（新）

```
语义解析(ordinal_references=["第一家"], merchant_mentions=["海底捞"])
  → context_recovery: 恢复"第一家"的 shop_id
  → target_resolve:
      _resolve_context_targets() → 第一家 shop_id
      _resolve_explicit_targets() → 海底捞 shop_id
      合并 → ≥ 2 → RESOLVED
  → comparison_planner → ... → answer
```

## 3.7 风险与回归控制

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| explicit comparison 回归 | 低 | 现有 comparison 测试不修改，确保仍通过 |

| 多轮状态污染 | 中 | CandidateSet 当前轮有效，不跨轮 persist |
| LLM 编造候选条件 | 低 | CandidateSpec 由规则提取器兜底校验 |
| 测试覆盖不足 | 中 | 新增 `test_discovery_comparison.py` |
