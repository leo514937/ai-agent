# 1. 当前架构链路分析

> 基于 `graph_builder.py`、`semantic/`、`target/`、`planning/`、`answer/` 的实际代码，
> 从用户输入到最终回答的完整节点链路，标出 recommendation / comparison / single_shop_query 的差异。

## 1.1 完整节点链路

```
START
  ↓
receive_input          — 组装 TurnInput
load_session_state     — 从 InMemorySessionStore 加载
check_pending          — 检查是否有待处理的澄清
  ├─ restore → target_resolve（用户回复编号）
  ├─ invalid/expired → clarify_response
  └─ normal → basic_input_validate
basic_input_validate   — 空/过长校验
  ├─ error → emit_response
  └─ ok → normalize_text
normalize_text         — 文本归一化
hard_guard             — 敏感词/问候检测
  ├─ 非 safe → emit_response
  └─ safe → top_intent_router
top_intent_router      — LLM 判断顶层意图
  ├─ 非 local_life → emit_response
  └─ local_life → semantic_parse
semantic_parse         — LLM 解析语义帧（SemanticFrame）
slot_extractor         — 规则补充提取（店铺名/序数/指示词/facet）
frame_validator        — 校验语义帧
  ├─ error → clarify_response
  └─ ok → context_recovery
context_recovery       — 恢复上下文引用（"第一家"/"这家"）
target_resolve         — 解析目标 shop_id    ← ★ 核心分叉点
  ├─ recommendation → 合成 RESOLVED（shop_id="recommendation"）
  ├─ comparison     → 尝试解析 ≥2 个 shop_id
  └─ single_shop    → resolve_shop()
clarify_decide         — 根据解析结果决策
  ├─ RESOLVED        → task_plan
  ├─ AMBIGUOUS       → clarify_response（让用户选）
  ├─ NOT_FOUND       → emit_response
  └─ comparison 不足  → emit_response（"请补充店名"）
task_plan              — route_task() 按 task_type 分流
  ├─ recommendation → facet_plan
  └─ comparison     → comparison_planner
facet_plan             — 按 facet 生成 tool_calls（get_shop_detail / check_open_status...）
comparison_planner     — 按 shop_id 列表生成 tool_calls（每店多 facet）
plan_validator         — 校验 tool_calls（工具注册/参数/预算）
  ├─ pass → tool_execute
  └─ fail → fallback_answer
tool_execute           — 执行所有 tool_calls（已优化为批量并发）
  ├─ required 失败 → fallback_answer
  └─ ok → evidence_build
evidence_build         — 构建 EvidencePack / ComparisonMatrix / RankingSnapshot
answer_plan_build      — 构建 AnswerPlan
answer_generate        — LLM 或模板生成最终回答
answer_verify          — 校验回答安全性
  ├─ pass → final_response_build
  ├─ rewrite_needed → rewrite → answer_generate（重试）
  └─ rewrite 超限 → fallback_answer
final_response_build   — 组装最终响应
state_update_plan      — 生成 SessionWriteDirective
persist_session_state  — 写回 InMemorySessionStore
emit_response          → END
```

## 1.2 三路 task_type 差异

### recommendation 路径

```
semantic_parse(task_type=recommendation)
  → slot_extractor(merchant_mentions=[], query_terms=["ktv"], scene_terms=[])
  → context_recovery(无引用)
  → target_resolve:
      发现 merchant_mentions=[] 且无引用
      → 合成 RESOLVED(shop_id="recommendation")
  → clarify_decide(RESOLVED → task_plan)
  → task_plan(route_task → recommendation)
  → facet_plan(生成 search_shops + placeholder 调用)
  → plan_validator
  → tool_execute(search_shops → 批量 get_shop_cards / get_shop_detail / check_open_status ...)
  → evidence_build(build_recommendation_evidence → ranking_snapshot)
  → answer_generate(推荐回答)
```

关键特点：
- **不解析具体 shop_id**，合成 RESOLVED 绕过 target_resolve 校验
- 工具调用使用 `$search_result[0].shop_id` 占位符
- `_h_tool_execute` 会额外注入 hidden_calls（get_shop_cards + get_shop_review_summary）

### comparison 路径（当前）

```
semantic_parse(task_type=comparison)
  → slot_extractor:
      merchant_mentions=["海底捞","山城一锅"] 或 []
      comparison_targets=[{shop_name:"海底捞",reference:"explicit"},...]
  → context_recovery:
      如有 ordinal/deictic → resolve_references() 从 session 恢复
  → target_resolve:
      merchant_mentions ≥ 2 → 直接 resolve 并返回
      merchant_mentions < 2 但有 comparison_targets
        → 逐个 resolve_shop() 尝试解析
        → 不足 2 个 → 返回 "comparison_requires_at_least_two_shops"
      merchant_mentions=[] 且无引用且无店名描述
        → 几乎必定触发少于 2 个错误
  → clarify_decide:
      comparison_requires_at_least_two_shops → emit_response("请补充另一家店名")
```

关键问题：
- **target_resolve 是硬阻塞**：必须在进入 task_plan 前拿到 ≥2 个 shop_id
- discovery 类型（无店名）完全无法通过

### single_shop_query 路径

```
semantic_parse(task_type=single_shop_query / coupon_query)
  → slot_extractor(merchant_mentions=["海底捞"])
  → target_resolve:
      resolve_shop("海底捞") → 获取 shop_id
      返回 RESOLVED
  → task_plan(route_task → single_shop_query)
  → facet_plan(按 facets 生成 tool_calls)
  → ...（后续工具执行和回答）
```

## 1.3 当前关键数据结构

### SemanticFrame（semantic/intent_parser.py L49-68）

```python
class _SemanticFrameRouterResponse:
    top_intent, task_type, primary_task
    facets: list[FacetSpecResponse]
    merchant_mentions: list[str]        # 显式店名 ["海底捞"]
    reference_mentions: list[str]       # ["第一家","这家"]
    comparison_targets: list[dict]      # [{shop_name, reference, source_text}]
    ordinal_references: list[str]       # ["第一家","第二家"]
    deictic_references: list[str]       # ["这家"]
    focused_facets: list[str]
    comparison_focus: str
    hard_constraints: dict
    soft_preferences: dict
    ranking_signals: dict
    follow_up: dict | None
    need_context: bool
```

### 缺失的能力

- **没有 `candidate_source` / `candidate_spec`**：无法区分 explicit/discovery/context
- **没有 `sort_by` / `limit` / `filters`**：用户的"评分最高""两家"无法结构化存储
- **`merchant_mentions` 和 `comparison_targets` 只接受店名**：把"评分最高的 KTV"当作文本中的店铺名来提取，自然会提取失败

### SessionState（domain/state.py L15-26）

```python
class SessionState:
    current_shop: dict | None
    last_recommendation_list: list[dict]
    active_constraints: dict
    pending_clarification: dict | None
    comparison_targets: list[dict]
    comparison_result: Any
    suggested_shop: dict | None
```

### SessionState 问题

- **没有 `last_candidate_set`**：无法恢复 discovery 候选
- **没有 `active_candidate_spec`**：refine 时丢失原始条件
- **`comparison_targets` 只存 shop_id**：无法追溯候选来源
