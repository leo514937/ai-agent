# 支持动态推荐数量

## 目标

当用户说"推荐 5 家"、"推荐 3 家"、"推荐 10 家"时，系统能根据用户指定的数量返回对应条数的推荐结果。

## 当前现状

推荐数量完全由全局硬编码常量 `RECOMMENDATION_FINAL_TOP_K = 5`（原为 3）控制。

所有用户输入，无论"推荐几家"、"推荐 3 家"还是"推荐 5 家"，都被视为"意图=推荐"，
数字部分被忽略，结果数量始终是 `RECOMMENDATION_FINAL_TOP_K`。

## 需要改动的位置

### 1. 语义层：提取用户期望的数量

**位置**：`semantic/intent_parser.py` 或 `semantic/slot_extractor.py`

当前 `intent_parser.py` 和 `slot_extractor.py` 只识别`"推荐"`、`"推荐几家"`、
`"帮我推荐几家"`等词来判断用户意图，没有提取数字的代码。

需要新增：
```python
# 在 slot_extractor.py 或 intent_parser.py 中
import re
def extract_recommendation_count(text: str) -> int | None:
    """从 '推荐5家'、'推荐 10 家'、'推荐几家' 中提取数量。
    
    Returns:
        数字 N（5、10…）或 None（未指定/"推荐几家"）
    """
    m = re.search(r'推荐\s*(\d+)\s*家', text)
    if m:
        return int(m.group(1))
    return None
```

提取的结果需要写入 `semantic_frame` 或 `SessionState` 中，
供下游消费。

### 2. 排名层：使用动态 top_k

**位置**：`planning/policies/ranking_policy.py:rank_candidates`

当前：
```python
def rank_candidates(candidates: list, preferences: dict) -> list:
    # ...
    return surviving[:RECOMMENDATION_FINAL_TOP_K]
```

需要改为支持可选参数：
```python
def rank_candidates(candidates: list, preferences: dict, top_k: int | None = None) -> list:
    k = top_k or RECOMMENDATION_FINAL_TOP_K
    # ...
    return surviving[:k]
```

调用方（`evidence_builder.py:_build_recommendation_evidence`）需要从
`semantic_frame` 或 `plan_dict` 拿到用户指定的 `top_k`，传给 `rank_candidates`。

### 3. 证据构建层：动态 candidate top_k

**位置**：`planning/evidence/evidence_builder.py:_build_recommendation_evidence`

当前 `_search_result_candidates` 用 `RECOMMENDATION_CANDIDATE_TOP_K = 8` 截断搜索候选。
`rank_candidates` 的 `top_k` 不能超过 `RECOMMENDATION_CANDIDATE_TOP_K`。

注意：当用户要求"推荐 10 家"时，`RECOMMENDATION_CANDIDATE_TOP_K` 目前是 8，
会导致即使 `top_k=10` 也只能拿到 8 个候选。

需要联动逻辑：
- 如果用户指定的 `top_k > RECOMMENDATION_CANDIDATE_TOP_K`，需要相应增大搜索召回和候选数量
- 或者直接移除 `_search_result_candidates` 的 `limit` 截断，使用 search_shops 的全量结果

### 4. 展示层：动态 limit

**位置**：`answer/composers/deterministic.py:RecommendationComposer.compose`

当前：
```python
ranking_lines = _format_ranked_shop_lines(ranking_items, limit=5)
```

需要将 `5` 替换为从 `plan` 或 `context` 读取的动态值：
```python
desired_count = (context or {}).get("desired_recommendation_count", RECOMMENDATION_FINAL_TOP_K)
ranking_lines = _format_ranked_shop_lines(ranking_items, limit=desired_count)
```

### 5. 推荐续问：动态 limit

**位置**：`engine/subgraphs/response_subgraph.py:_build_recommendation_refine_text`

当前：
```python
for idx, item in enumerate(items[:5], 1):
```

需要从 `state` 中读取预期的推荐数量。

## 数据流设计

```
用户输入"推荐5家"
  │
  ▼
intent_parser / slot_extractor
  │  提取 desired_count=5
  │  写入 semantic_frame.desired_recommendation_count = 5
  │
  ▼
planning_subgraph / _h_evidence_planner
  │  传给 build_recommendation_execution_plan
  │  写入 plan_dict["desired_recommendation_count"] = 5
  │
  ▼
evidence_builder / _build_recommendation_evidence
  │  top_k = plan_dict.get("desired_recommendation_count")
  │  rank_candidates(candidates, preferences, top_k=top_k)
  │
  ▼
ranking_snapshot → DecisionPlan.overall_ranking
  │
  ▼
RecommendationComposer.compose
  │  limit = plan.desired_recommendation_count or RECOMMENDATION_FINAL_TOP_K
  │  _format_ranked_shop_lines(ranking_items, limit=limit)
```

## 边界情况

| 输入 | 期望行为 |
|------|---------|
| "推荐几家" | 使用默认值 RECOMMENDATION_FINAL_TOP_K（5 家） |
| "推荐 3 家" | 返回 3 家 |
| "推荐 5 家" | 返回 5 家 |
| "推荐 20 家" | 受限于 RECOMMENDATION_CANDIDATE_TOP_K（8），最多返回 8 家 |
| "推荐 0 家" | 不合理输入，退化为默认值 |
| "推荐 -1 家" | 不合理输入，退化为默认值 |
| "推荐一百家" | 中文数字需额外处理，建议先忽略，使用默认值 |

## 与去重的关系

推荐数量增大到 5 后，品牌重复问题会更突出。
建议在实现动态数量之前或同时，先完成 `todo/定位分析.md` 中方案 B 的品牌级多样性裁剪。
否则用户说"推荐 10 家"可能看到 8 个海底捞。
