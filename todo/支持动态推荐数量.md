# 支持动态推荐数量

## 结论

这个问题已经完成修复。

当前系统已经支持用户在推荐类请求中显式指定数量，并沿用现有 `candidate_limit` 字段贯穿主链，不新增平行协议字段。

已支持的能力：

- “推荐 3 家附近火锅” -> 按 3 条截断最终推荐
- “推荐 5 家附近火锅” -> 按 5 条截断最终推荐
- 未指定数量 -> 继续走默认 `RECOMMENDATION_FINAL_TOP_K = 5`
- 请求数量过大 -> 使用现有 `SEARCH_LIMIT` 作为上限保护

## 设计原则

本次没有新增 `desired_recommendation_count` 这类新字段，而是复用现有：

- `semantic_frame.candidate_limit`

这样更符合仓库既有 schema，也避免再造一条独立的数据流。

## 修复前问题

修复前虽然默认推荐数已经从 3 调整为 5，并且品牌多样性裁剪已经存在，但系统仍然不真正理解用户说的“推荐 N 家”。

表现是：

- 用户说“推荐 3 家”，结果仍按固定默认数返回
- 用户说“推荐 10 家”，语义层没有稳定提取数量
- answer/composer/refine 仍然写死展示前 5 条

## 最终方案

### 1. 文本提取

在 `semantic/slot_extractor.py` 中新增数量提取：

- 支持 `推荐 3 家`
- 支持 `帮我推荐10家`
- 未指定数字时返回 `None`

提取结果直接写入：

- `candidate_limit`
- `ranking_signals.requested_count`

### 2. LLM 结果与规则 hints 合流

在 `semantic/intent_parser.py` 中：

- 如果 LLM payload 没给 `candidate_limit`
- 则用 slot extractor 的数量 hints 回填

这样即使 LLM 本身没显式产出数量，推荐主链也能稳定拿到。

### 3. 推荐计划层

在 `planning/plans/execution_plan_builder.py` 中：

- `candidate_limit` 会写入 recommendation plan
- enrichment top k 会根据用户请求数量扩张
- 但仍受现有 `SEARCH_LIMIT` 上限保护

也就是说：

- 默认仍是 5
- 用户要更多时，会放大 enrichment 数量
- 但不会无限制拉高

### 4. 排序层

在 `planning/policies/ranking_policy.py` 中：

- `rank_candidates` 现在支持 `top_k`

排序仍保留已有品牌级多样性裁剪和补位逻辑，只是最终裁剪条数从固定值改为动态值。

### 5. 证据构建层

在 `planning/evidence/evidence_builder.py` 中：

- recommendation evidence 会读取 `candidate_limit`
- `ranking_snapshot.candidate_limit` 会记录最终使用的条数
- `ranked` 会按请求数量截断

### 6. 回答展示层

在 `answer/composers/deterministic.py` 中：

- recommendation composer 不再固定展示 5 条
- 会优先读取 `semantic_frame.candidate_limit`

在 `engine/subgraphs/response_subgraph.py` 中：

- recommendation refine follow-up 也不再固定切前 5 条
- 会跟随当前请求数量

## 与品牌去重的关系

动态数量和品牌多样性现在是兼容的：

- 先做已有的品牌级多样性裁剪
- 不足时再按原排序补位
- 最后按 `candidate_limit` 截断

这避免了“推荐 10 家就出现 8 家同品牌”的问题继续恶化。

## 边界行为

| 输入 | 当前行为 |
|---|---|
| `推荐几家附近火锅` | 使用默认 5 |
| `推荐 3 家附近火锅` | 返回至多 3 条 |
| `推荐 5 家附近火锅` | 返回至多 5 条 |
| `推荐 20 家附近火锅` | 受 `SEARCH_LIMIT` 保护 |
| `推荐 0 家附近火锅` | 退回默认值 |
| `推荐 -1 家附近火锅` | 退回默认值 |

当前仍未额外支持的输入：

- 中文大写数字，如“推荐三家”
- 更复杂的数量表达，如“先给我来五六家”

这些不影响当前主目标，后续可以单独增强。
