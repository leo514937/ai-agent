# P1.5 Day 7 - Tool Harness & Final Response Safety

优先级：第七。

目标：把工具链、最终回答安全、评测记录和 trace 完整兜起来，确保工具失败、空结果、权限失败都不会被误说成“没有券”。

## 这一天要解决什么

- 工具输出先归一化
- 工具错误先分类
- 最终回答先做安全裁剪
- 最终回答不能暴露内部字段
- 关键 case 要可自动记录

## 实现要求

- 工具归一化、错误分类、最终安全、评测记录要分层实现，不要写在同一个“大后处理函数”里
- tool harness 要保留清晰的输入输出边界，避免把业务判断和工具适配写混
- final response safety 要独立成层，不能把安全裁剪和文案生成搅在一起
- 评测记录和 trace 写入要模块化，避免回头再长成一个巨型出口函数

## 重点任务

### 1. `tool_result_normalizer`

把不同工具的结果归一化到一致结构。

要求：

- 不同 tool 的 output 可以统一消费
- `success / empty / error / degraded` 可区分
- 结构化字段不要在 final answer 里原样泄漏

### 2. `tool_error_classifier`

工具错误需要明确分类，而不是一把抹平。

建议分类：

- `timeout`
- `not_found`
- `empty_result`
- `permission_error`
- `invalid_params`
- `service_unavailable`

### 3. `realtime_result_degrade_policy`

实时工具失败时，不能把“失败”伪装成“没有数据”。

例如：

- 券接口 timeout 不能回答“没有券”
- 权限错误不能回答“商家没有开放”
- empty_result 和 error 要区分

### 4. `final_answer_safety`

最终回答必须通过安全检查。

检查点：

- forbidden facets 是否出现
- 是否泄漏内部字段
- 是否把弱证据说成强结论
- 是否把工具失败误说成确定结果

### 5. `final_answer_audit`

把最终答案和其依据一起审计，便于回放和分析。

### 6. `eval_case_recorder`

将关键 case 自动记录到评测系统，方便后续回归。

### 7. `trace_writer`

确保关键路径在 trace 里完整可见，能从输入一路追到最终答案。

## Day 7 输出要求

Day 7 结束后，工具和最终响应应该满足：

- 工具失败不被伪装成无数据
- 最终回答不暴露内部字段
- 最终回答不违反 contract
- 关键路径可被 trace / eval 记录
- 空结果、失败结果、降级结果都可区分

## Day 7 验收

- 工具超时不能回答“没有券”
- empty_result 和 tool_error 区分
- final answer 不暴露内部字段
- final answer 不违反 contract
- eval case 自动记录关键路径
- trace_writer 覆盖全链路
