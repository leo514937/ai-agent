# P1.5 Day 6 - RAG Pipeline Upgrade

优先级：第六。

目标：把本地生活 RAG 从“召回一个东西”升级成“召回 - 过滤 - 排序 - 证据化”的分层 pipeline，确保不串店、不串 facet、不把弱证据当强证据。

## 这一天要解决什么

- 构建本地生活版的分层 RAG pipeline
- 让 recall / filter / rerank / evidence_pack 分层清晰
- 保证问券不召回环境，问环境不混入券
- 保证同一店铺的证据不串到别的店

## 实现要求

- RAG pipeline 要按 recall / filter / rerank / evidence_pack 分层，不要把所有逻辑塞进单个检索入口
- 召回、过滤、排序、证据化要分别实现，避免一个函数同时处理太多职责
- 各类 filter 要独立可测，方便单独验证不串店、不混 facet
- 证据包生成要和最终回答生成解耦，避免证据处理逻辑侵入回答模板

## 目标 pipeline

```text
recall
→ meta_fetch
→ merge
→ filter
→ rerank
→ evidence_pack
```

## 重点任务

### 1. 多路召回

至少支持：

- dense recall
- sparse recall
- metadata recall
- parent-child recall

### 2. 过滤层

召回后必须有明确过滤层：

- `shop_id` filter
- facet filter
- stale_data_filter
- duplicate_review_filter
- low_relevance_filter

### 3. 排序层

在过滤后进行 rerank，不要直接拿原始 recall 结果进答案。

### 4. `evidence_pack`

最终 RAG 输出要形成可 review 的证据包。

证据包要能够表达：

- items
- strong / weak evidence
- citations
- discard summary
- 证据状态

## 重点约束

- 不串店
- 不把环境证据塞到券问题里
- 不把券证据塞到环境问题里
- 不把低相关证据直接当成结论
- 空证据必须可降级，而不是硬答

## Day 6 输出要求

Day 6 结束后，RAG 层应该能稳定回答：

- 召回的是不是同一家店？
- 召回的证据是不是这个 facet 对应的证据？
- 召回结果是不是足够强，可以进入 review？

## Day 6 验收

- RAG 不串店
- 问券不召回环境
- 问环境不混入券
- 低相关证据被过滤
- 空证据进入 degrade
- `evidence_pack` 可被 review 使用
