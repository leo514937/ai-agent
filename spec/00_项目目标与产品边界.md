# 00 项目目标与产品边界

## 1. 项目定位

本项目目标是构建一个“问小团类”的本地生活助手 Agent。它面向真实用户的本地生活消费决策场景，通过自然语言对话理解用户需求，调用真实工具获取商家、优惠券、团购、营业状态、距离、评价摘要等事实信息，并基于这些证据给出可信、有用、自然的查询、推荐、对比和解释。

本项目不是简单 FAQ，不是固定模板问答，也不是只靠 LLM 自由生成的聊天机器人，而是一个以真实业务数据和工具调用为事实来源、以 LangGraph 为编排控制核心、以 LLM 为语义理解和自然表达能力的本地生活 Agent。

## 2. 产品目标

系统最终要帮助用户更快、更可信地完成本地生活选择，例如吃什么、去哪家店、哪家更划算、哪家更适合某个场景、某家店是否有券、是否营业、离我多远等。

核心目标包括：

1. 理解用户自然语言中的本地生活意图。
2. 识别用户关心的消费维度：距离、价格、评分、优惠、营业状态、环境、口味、服务、排队、适合场景等。
3. 通过真实 ToolCall 获取事实，而不是依赖模型编造。
4. 支持单店查询、附近推荐、多店对比、条件筛选、场景化推荐、多轮追问。
5. 在信息不足、多候选歧义、工具失败时能补充查询或可信降级。
6. 最终回答自然、有推荐感，但所有事实必须能回溯到 ToolResult / EvidencePack。

## 3. 用户问题类型

系统需要覆盖真实用户在本地生活场景中的复杂 query，而不是只覆盖固定句式。

典型问题包括：

- “附近有没有适合约会、现在营业、最好有券的火锅？”
- “海底捞水晶城店怎么样，有没有优惠？”
- “山城一锅这家店有券吗，环境评价怎么样？”
- “这家和海底捞比呢？”
- “便宜一点的呢？”
- “第一家有券吗？”
- “这几家哪个评分高、离我近、性价比也不错？”
- “带长辈吃饭，附近哪家更稳一点？”

## 4. Agent 能力边界

本 Agent 主要处理本地生活消费决策相关任务：

- 商家搜索与查询
- 优惠券 / 团购查询
- 营业状态查询
- 距离 / ETA 查询
- 商家评价摘要
- 附近推荐
- 条件筛选
- 多店对比
- 场景化推荐
- 多轮指代恢复
- 推荐理由解释

系统不应承担以下任务：

- 不编造不存在的商家、优惠券、评分、团购、距离、营业状态。
- 不在没有工具结果的情况下给确定性事实。
- 不代替用户完成真实支付、下单、预约等强交易行为，除非后续明确接入真实交易工具和确认流程。
- 不回答违法、危险或明显越界请求。
- 不把普通闲聊和能力说明强行路由到本地生活工具链路。
- 不把医疗、法律、金融投资等高风险专业建议伪装成本地生活推荐。

## 5. 成功标准

项目成功不是“跑通几个固定样例”，而是具备真实用户表达的泛化处理能力。

验收标准包括：

1. 本地生活 query 能正确进入 Agent 主链路。
2. 非本地生活问题能直接回答。
3. 单店问题能绑定明确 shop_id。
4. 多候选时不默认第一家，而是展示候选。
5. 推荐问题能理解品类、距离、预算、评分、优惠、场景等约束。
6. 对比问题能进入多店对比链路，而不是误入单店查询。
7. 多轮追问能理解“这家”“第一家”“便宜一点的呢”等上下文表达。
8. 工具失败、空结果或证据不足时能可信降级。
9. 最终回答不出现无来源事实。
10. 主链路不依赖 mock 数据、mock 工具或静态假结果。
