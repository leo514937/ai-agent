# 05 工具调用与可信数据约束

## 1. 设计目标

本项目必须以真实工具调用作为事实来源。LLM 可以理解、规划和表达，但不能替代工具生成事实。

工具层目标是：

1. 统一注册。
2. 统一调用。
3. 统一 schema 校验。
4. 统一错误表达。
5. 统一 trace。
6. 防止 mock、静态数据和幻觉进入主链路。

## 2. ToolRegistry

所有工具必须注册到 ToolRegistry。

ToolRegistry 至少维护：

- tool_name
- description
- input_schema
- output_schema
- timeout
- retry_policy
- backend_source
- whether_readonly
- whether_requires_confirmation

不允许 LLM 或业务节点直接调用未注册工具。

## 3. ToolCallGateway

所有工具调用必须经过 ToolCallGateway。

Gateway 职责：

- 参数校验。
- 工具查找。
- 调用执行。
- 超时控制。
- 错误捕获。
- 结果标准化。
- trace 记录。
- backend_source 标记。

禁止：

- 绕过 Gateway 访问数据库。
- 绕过 Gateway 读取静态 JSON。
- 绕过 Gateway 调 Java 接口。
- 在节点内部临时拼接假结果。

## 4. 工具能力范围

建议至少支持以下工具：

- resolve_shop：商家解析。
- search_shops / search_restaurants：商家搜索。
- get_shop_detail：商家详情。
- get_coupon_list：优惠券列表。
- get_deal_list：团购套餐。
- check_open_status：营业状态。
- get_distance_eta：距离和到达时间。
- get_shop_review_summary：评价摘要。
- get_shop_cards：商家卡片。
- compare_shops：多店对比所需事实聚合。

## 5. 输入输出 Schema

每个工具必须有明确输入和输出结构。

输入 schema 应约束：

- 必填字段。
- 字段类型。
- 枚举值。
- 数量上限。
- 字符串最小长度。
- shop_id 是否必须。
- location 是否必须。

输出 schema 应约束：

- status。
- data。
- error_type。
- error_message。
- backend_source。
- trace_id。

## 6. 错误类型

工具失败不能只返回 None。

建议错误类型：

- empty_result
- invalid_argument
- timeout
- backend_error
- unavailable
- permission_denied
- unsupported
- rate_limited

每种错误都应进入 Review，由 Review 决定澄清、补工具、重规划、部分回答或可信失败。

## 7. 禁止 Mock 进入主链路

正常运行链路禁止使用：

- mock 商家数据。
- mock 优惠券。
- mock 营业状态。
- mock 距离。
- 静态店名表。
- 静态团购列表。
- hardcoded query 结果。
- 工具失败后的假成功结果。

允许：

- 单元测试中的 fake / stub。
- 测试 fixture。
- 本地隔离 test database。
- 显式标记的测试 backend_source。

要求：

- 测试 fake 不得混入生产配置。
- backend_source 必须可追踪。
- 主链路发现 mock source 应作为验收失败。

## 8. 事实可信约束

以下事实必须来自工具：

- 商家是否存在。
- shop_id。
- 店名。
- 地址。
- 评分。
- 人均。
- 优惠券。
- 团购套餐。
- 营业状态。
- 距离。
- ETA。
- 评价摘要。

LLM 不能自行补充这些事实。

## 9. EvidencePack 绑定

工具返回事实后必须进入 EvidencePack。

每条事实建议绑定：

- fact_type
- value
- source_tool
- source_status
- shop_id
- confidence
- timestamp
- missing_reason

最终回答引用事实时，只能使用 EvidencePack 中存在的内容。

## 10. 验收要求

工具链路验收应检查：

1. 所有工具是否注册。
2. 是否经过 Gateway。
3. schema 是否生效。
4. 错误是否显式表达。
5. 空结果是否可区分。
6. backend_source 是否正确。
7. 是否存在 mock 混入主链路。
8. 最终回答是否出现工具未返回事实。
