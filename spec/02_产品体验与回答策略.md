# 02 产品体验与回答策略

## 1. 产品体验目标

问小团类本地生活助手的体验目标不是“把数据库字段读出来”，而是帮助用户完成消费决策。最终回答应该像一个可靠的本地生活导购：结论明确、理由充分、边界清楚、语气自然。

理想回答应具备：

1. 先给结论。
2. 再给推荐或对比理由。
3. 明确适合什么场景。
4. 明确不确定或缺失信息。
5. 避免机械堆叠工具结果。
6. 避免无证据的夸张推荐。

## 2. 回答基本结构

对于推荐类问题，建议结构：

```text
结论：我更推荐 A / 可以优先看这几家。
理由：结合距离、评分、优惠、营业状态、场景偏好说明。
候选：列出 2~5 家，说明各自适合什么情况。
提醒：说明缺失信息或工具不确定项。
追问：必要时询问用户是否要继续按价格、距离、券筛选。
```

对于对比类问题，建议结构：

```text
结论：如果你更看重 X，选 A；如果更看重 Y，选 B。
对比维度：价格、距离、评分、优惠、营业、评价、场景适配。
差异解释：说明每家优势和短板。
最终建议：给出明确选择建议。
```

对于单店查询，建议结构：

```text
概览：这家店整体如何。
事实：券、营业、距离、评分、评价摘要等。
适合：适合什么人或场景。
注意：缺失信息或不确定项。
```

## 3. 直接回答策略

当用户问题不属于本地生活任务时，应直接回答。

示例：

- “你有什么作用？”
- “这个项目架构怎么设计？”
- “什么是 ToolCall？”

要求：

- 不调用本地生活工具。
- 不强行进入商家推荐链路。
- 回答用户真实问题。
- 如果用户问题包含本地生活任务和普通问题，应拆开处理。

## 4. 本地生活回答策略

本地生活回答必须基于 EvidencePack。

允许 LLM 做：

- 组织语言。
- 提炼结论。
- 解释推荐理由。
- 做口语化表达。
- 根据证据说明适合场景。

不允许 LLM 做：

- 新增工具没有返回的优惠。
- 编造评分、距离、营业状态。
- 把没有证据的评价说成确定事实。
- 编造商家存在。
- 为了回答好听而隐藏工具失败。

## 5. 推荐体验原则

推荐类回答要避免只给“找到 3 家”。

不推荐回答：

```text
找到 3 家火锅店：A、B、C。
```

推荐回答：

```text
我建议你优先看 A。它离你更近，目前有券，评分也比较稳定；B 更便宜，但评价里对排队反馈较多；C 环境更好，适合约会或朋友聚餐。你如果更看重便宜，可以选 B；如果想稳一点，选 A。
```

## 6. 对比体验原则

对比类回答不能只做字段罗列，而要给决策建议。

要求：

- 说明每家优势。
- 说明每家短板。
- 说明适合人群或场景。
- 给出“如果你更在意什么，就选哪家”的建议。
- 对缺失维度明确标注“暂无证据”。

## 7. 多轮体验原则

用户追问时，系统应该像记得刚才聊过什么一样自然回应。

示例：

用户：“附近推荐几家火锅。”

助手：“我建议优先看 A、B、C……”

用户：“便宜一点的呢？”

系统应理解为：在上一轮火锅候选或同类范围内，重新按价格偏好筛选或排序，而不是把“便宜一点”当成新问题。

要求：

- 保持上下文连续。
- 保留上一轮候选和约束。
- 用户新增约束时应合并，而不是覆盖全部上下文。
- 如果用户明显换话题，再重置上下文。

## 8. 澄清体验原则

澄清不是失败，而是可信体验的一部分。

需要澄清的情况：


- “这家”无法确定。
- “第一家”没有上一轮候选。
- 对比对象过多。
- 关键条件缺失，且无法合理默认。

澄清应具体、可选择。

不推荐：

```text
请提供更多信息。
```

推荐：

```text
我找到 3 家名字相近的店：1. 海底捞水晶城店；2. 海底捞牡丹园店；3. 海底捞西直门店。你想问哪一家？
```

## 9. 可信降级体验

工具失败或证据不足时，应给出可理解的降级回答。

示例：

```text
我查到了这家店的基本信息和距离，但优惠券工具这次没有返回结果，所以不能确定它现在是否有券。基于已查到的信息，它距离你较近，评分也不错；如果你主要想找有券的店，我可以继续帮你换几家有券候选。
```

要求：

- 不隐藏失败。
- 不夸大不确定信息。
- 能给出下一步选择。
